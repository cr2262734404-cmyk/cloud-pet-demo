## 本地启动

需要可运行的 Node.js；本项目使用标准库，没有 npm 第三方依赖。

```powershell
cd "本项目所在目录"
node server.mjs
```

电脑打开 [http://127.0.0.1:4173/](http://127.0.0.1:4173/)。启动日志和 [网络地址接口](http://127.0.0.1:4173/api/network) 会显示本机局域网地址。手机与电脑处于同一可互通 Wi-Fi 后，在手机浏览器打开对应的 `http://电脑IP:4173/`。电脑和 Node 服务需保持运行。

端口可通过 `PORT` 环境变量修改。若手机无法连接，先核对 Wi-Fi、IP 和服务是否运行，再检查当前网络是否隔离设备、系统是否允许该服务接受连接。程序不会自动改动防火墙。

## 三端入口

顶部「H5 演示」面板可切换角色、模拟门店、演示说明与手机自检；顶部季节按钮可切换季节、时段、自动模式与轻量模式。

- 顾客：`/#customer/home`，或 `?role=customer`。
- 老板：`/#owner/today`，或 `?role=owner`。
- 员工：`/#staff/work`，或 `?role=staff`。
- 手机测试记录：`/#customer/device-test`。

两家模拟门店分别为云朵宠物与青禾宠物。角色选择是演示入口，不是生产登录。

## 数据模式

| 模式 | 保存位置 | 联动范围 |
| --- | --- | --- |
| 本地 Node / 局域网 H5 | `data/demo.json` | 连接同一服务的不同手机和角色 |
| GitHub Pages / 纯静态 H5 | 当前浏览器 localStorage | 同一浏览器内三角色；不同设备各自独立 |

页面会说明当前模式。静态版不具备跨设备共享数据库；浏览器清理站点数据会清除本地演示操作。上传照片也保存到对应演示存储中，不应放入真实客户隐私资料。

## 建议演示路线

1. 顾客查看服务，选宠物与可用时段，提交预约。
2. 切老板端查看排期并确认预约、安排护理师。
3. 切员工端登记到店、开始护理、一次提交完成服务和护理手记。
4. 回顾客端查看护理手记与质检确认后的小礼物。
5. 老板在机会雷达选择未被拦截的机会，查看原因、标记人工联系或执行模拟授权渠道。
6. 从该机会建立预约，完成服务并确认消费金额，再查看结果归因。

消费、消息、礼物生成都属于演示流程，没有真实支付和真实消息发送。礼物使用宠物原照片与主题装饰，不宣称已经接入 AI 宠物外貌生成。
