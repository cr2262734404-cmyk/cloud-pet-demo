# 顾客端实现与验收交接

实现文件：`dist/customer.js`、`dist/customer.css`。通过共享 `ctx` 和同一模拟引擎读写；不内置另一份业务样本。主壳负责三端切换、门店切换、16 主题、三项底部导航与图片导出预览。

| 页面 | 路由 | 实际交互 |
|---|---|---|
| C01 首页 | home | 胶囊菜单、预约入口、服务/手记/门店、近期预约与手记 |
| C02 服务列表 | services | 分类筛选、服务详情 |
| C03 服务详情 | service/s1 | 价格、时长、适用宠物、护理师、开始预约 |
| C04 选择宠物 | select-pet | 选择自己的健在宠物、增加宠物后返回预约 |
| C05 选择时段 | booking | 宠物适用服务筛选、日期、员工、匿名排期占用、时长与闭店约束 |
| C06 确认预约 | confirm | 核对完整资料、同意确认、服务端提交与冲突错误 |
| C07 预约成功 | success/a1 | 真实返回预约 ID、预约详情与首页入口 |
| C08 我的预约 | appointments | 进行中、结束、全部筛选 |
| C09 预约详情 | appointment/a1 | 状态进度、消费记录、改期、取消原因、完成报告、再次预约 |
| C10 我的宠物 | pets | 关联宠物列表、新增档案、护理手记入口 |
| C11 宠物详情 | pet/p1 | 体重/生日/绝育/偏好/注意事项、报告与服务历史 |
| C12 编辑宠物 | pet-edit/p1 | 表单验证、猫狗类型、照片上传与 JPEG 压缩、保存联动 |
| C13 手记列表 | reports | 按宠物筛选、打开记录 |
| C14 手记详情 | report/r1 | 毛发/耳部/指甲、表现、寄语、照片对比、建议、自动更新已查看、导出完整纪念卡 |
| C15 专属礼物 | gift/g1 | 已质检礼物原图、主题卡导出、复制文案、换风格咨询入口 |
| C16 联系门店 | contact | 电话展示/复制、地址复制、营业信息、预约 |
| C17 个人中心 | profile | 关联入口、称呼与偏好保存；`profile.save` 固定当前顾客 |
| C18 消息订阅 | messages | 服务与营销授权分开保存、模拟消息记录、撤回授权 |

## 验证记录

- `node --check dist/customer.js` 通过。
- 导入真实 `DemoEngine.getState('cloud','customer')` 与 `ui.js`，18 主路由渲染通过。
- 首页 4 季 × 4 时段渲染通过（共 34 次 render smoke 检查）；这不是截图与真机验证。
- 选择猫咪 p2 时，不兼容的犬服务自动切换至适用服务，已实测动作处理器。
- 预约变更复用原服务且排除自身占用；后端二次检查冲突、种类、技能与闭店时间。
- 资源通过 `ui.asset` 处理 Pages 子路径；自定义上传为 data URL。
- 顾客端已完成18路由截图、54组三宽度检查与完整预约/宠物/导出操作，详见 docs/customer-qa.md；Android/iPhone 真机仍须实际使用后提交，不标作已通过。

## 截图准备

`customerRoutes` 导出 18 主页面及 seed ID。C06 需要先设置 `ctx.draft.booking={petId:'p1',serviceId:'s1',employeeId:'e1',date:ctx.state.today,time:'13:00',notes:''}`。不设置时会展示“还差一个见面的时间”的真实空状态；C07 可直接传 a1。

## 边界与后续

- 预约表单目前展示未来 30 天，后端允许 90 天；这是有意选择较短可视范围。
- 不发起真实电话、消息或支付；礼物为已标注的照片与预设主题演示。
- 手机照片读取会压缩到最长边 1000px；超过 15MB 或浏览器无法解码的 HEIC 会给出实际错误。
- 保存原图与护理卡统一触发 `image-export`，由主壳展示可长按保存的图片。
- 用户可编辑自己的宠物与偏好；报告由员工维护，顾客仅查看和保存。
- 需要正式上线时，替换 Demo 身份、授权、数据持久化与图片存储，增加真实微信小程序安全与消息能力。
